## [2026-09-27] F1 孤立数字（第 0 位置）的表征在中后层几乎不含数字信息

- 结果（"跨数字方差" = 30 个数在 4096 维上的方差之和，衡量状态里有多少随数字变化的信息）：

| 层 | 孤立数字 范数 | 算式中 A 范数 | 孤立数字 跨数字方差 | 算式中 A 跨数字方差 |

| 8 | 4.5 | 11.9 | 2.1 | 23.5 |

- 解读：
  - 孤立数字放在第 0 位置时，从第 ~8 层起状态几乎与数字无关（跨数字方差从 16 降到 <1），而同一个数在算式里的方差随层增长到数百。中层差距 50–400 倍。
  - 合作者的 helix 目标 M_L(x) 正是从 (i) 拟合出来的：中后层的"流形"只拟合了一个几乎不随数字变化的残差。先做 StandardScaler 会把这点微小的方差放大到单位方差，所以拟合图看起来可能仍然像 helix。
  - 流形 LoRA 在中后层把算式中的 A 拉向 M_L(A)，等于拉向一个近似常数的向量，可能在抹掉数字信息。
  - 之前怀疑的"第 0 位置 massive activation"**不成立**：孤立数字的范数反而很小（~5），MSE 也不集中在少数维度（top-5 维只占 8–25%）。
- 注意：这是 main 上的测量；合作者默认用的 main_ref 目标正来自 main。stage1 checkpoint 上是否相同，待 sweep 验证。

## [2026-09-27] F2 三项式 A+B+C：中间和 a+b 在 B 和第二个 '+' 处可被解码，但单独替换第二个 '+' 不影响答案

- 设置：main；`Output ONLY a number.{a}+{b}+{c}=`，a,b,c∈10..99，总和≤99。base 准确率 74.8%（6000 题）。
  任务 `005-exp2-main`，commit 6e43655，`results/005-exp2-main/`。
- ⚠️ **更正（2026-09-27 05:10）**：下面的探针数字作废。交叉验证是按题随机切分的，同一 (a,b) 对搭配不同 c 会同时出现在训练折和测试折，而 B / 第二个 '+' 处的状态只由 (a,b) 决定，探针可以靠记忆过关：几乎未训练的 stage1-step150 也"解码"出 a+b 约 51%（B）/52%（op2）。已改为按 (a,b) 对分组切分（随机小模型上降到 2–3%），main 与早期 checkpoint 的探针重跑中（任务 020–023）。**因果部分（interchange / knockout / steering）不受影响。**
- 探针（旧版，作废）：交叉验证精确解码（1500 题，不按对错过滤；机会水平约 1–3%）。
  - a+b 在 **B 位置**从第 ~3 层起可解码（0.66–0.74）；在**第二个 '+'** 处 0.56–0.73，第 21 层起达 **0.97**。
  - 对照：打乱标签 0.02–0.03；用真实 f(a)、f(b) 线性解码 a+b 0.079；用 one-hot(a)⊕one-hot(b) 的加性解码器 0.043（exp2b 的参考值，CPU 测试）。→ 这是模型真实组合出来的和，不是"a、b 都在"造成的假象。
  - 总和 t=a+b+c 只在 **'=' 处、第 ~21 层起**才出现（0.70→0.97+）；C 位置对 a+b 的解码直到 27 层才到 0.4。
- 因果（单位置 interchange，300 道答对的题，捐赠题的 a'+b'≠a+b）：
  - 在**第二个 '+'** 处换成捐赠题的状态：**所有层答案都不变**（stay 0.98–1.00，捐赠和 0.00）。
  - 在 A 或 B 处替换：前 ~18 层答案会被改变（stay ≈0.05），但几乎不会变成 a'+b'+c；第 21 层起不再有影响。
  - 用 helix（W_s）平移 a+b：在 B、第二个 '+' 都几乎无效（≤0.03）。
- 暂定解读：模型在 B / 第二个 '+' 处**表征**了中间和，但最终答案并不依赖第二个 '+' 处的这份信息（至少单独替换它不改变结果）。可能是冗余（'=' 直接从 A、B 读操作数），也可能是这份中间和根本没被使用。
- 待验证（exp2b，任务 018）：替换后答案具体变成了什么（a'+b+c？a+b'+c？）、只保留第二个 '+' 时是否足够、attention knockout。

### F2 更新（exp2b，任务 `018-exp2b-main`，commit 6048163）：中间和"被表征但未被使用"

300 道 main 答对的题，捐赠题的 a'≠a、b'≠b 且 a'+b'≠a+b；base 准确率 76.8%，所以约 75% 是"完全跟随"的上限。
- 在 **A** 处替换（第 0–16 层）→ 答案变为 **a'+b+c**（0.70–0.75）；在 **B** 处替换 → 答案变为 **a+b'+c**（0.69–0.75），变成捐赠和 a'+b'+c 的比例为 **0.00**。
  B 处的捐赠状态里本来就含有 a'+b'（探针能解码约 70%），但答案只取走了其中的 b'。
- 同时替换 A、op1、B，**保留第二个 '+'**（其中已存有原题的 a+b）→ 答案跟随捐赠题（a'+b'+c，0.71–0.75），与四个位置全换时完全相同。**中间和既不必要，也不充分**。
- 第 18–20 层是转折点：此后替换 A、B 都不再影响答案，信息已被搬到 C / '=' 处。
- attention knockout（C、'=' 在所有层都看不到某位置）：挡住 A、B 或第二个 '+'，准确率都跌到 ≤0.03。
  但第二个 '+' 被挡时的崩溃不能归因于数字信息：换成捐赠题的 '+' 状态毫无影响，说明模型需要的是这个位置上"运算符/结构"一类的信息，而不是其中的 a+b。
  挡住 A 也会崩溃，尽管 a 在 op1、B、第二个 '+' 处都能 100% 解码 → 答案电路只从 a 自己的 token 位置读取它，其他位置的副本没有被使用。
- **结论（main，加法，两位数，总和≤99，单一 prompt 格式）**：模型在 B 和第二个 '+' 处算出并表征了中间和（解码准确率最高 97%，远高于加性对照的 4%），但最终答案是在约第 16–20 层由 C / '=' 直接从 A、B、C 三个位置分别读取操作数一次算出的；这份中间和在因果上是闲置的。
- 局限：只测了 main 和一种 prompt 格式；干预都是单层的；只分析了模型答对的题。发育 sweep（任务 009–017）会给出各 checkpoint 上的同一套测量。

## [2026-09-27] F3 相位旋转：helix 编辑能让答案 ±1、±2，但动不了十位

- 设置：main；二项 `Output ONLY a number.{a}+{b}=`（base 准确率 94.0%，5050 题）。任务 `004-exp1-main`，commit 6e43655，`results/004-exp1-main/`。
  helix map 在算式上下文的 A 位置（及 B 位置，与 a 联合拟合）上拟合；每个 Δ 用 200 道答对的题。
- 拟合：A 位置 helix 的交叉验证 R² 为 0.14（L0）→ 0.32（L21–27）；错误周期 ≤0.10，只用线性项 ≤0.18，打乱标签 <0。
  → helix 结构确实存在，但只解释了随数字变化的方差中约三分之一。
- 编辑 helix 子空间（8 维，范数约为状态的 1/3，最佳层 A=16、B=12；数值为答案变成 a+b+Δ 的比例）：
  - Δ=±1、±2：0.65–0.79；Δ=±5：0.24–0.63；**Δ=±10、±20：0.00–0.10**（B 位置 Δ=−20 例外，为 0.32）。
  - 同范数的随机方向（与 helix 子空间正交）：**0.00**，答案 98% 不变 → 效果是 helix 子空间特有的。
  - 真实差值投影到 helix 子空间后，效果与拟合的 helix 编辑相近（小 Δ 0.43–0.73，Δ=±10 ≤0.10）。
  - 整位置替换（上界）：各 Δ 都在 0.85–0.98。
  - 单周期编辑：只改 T=10、只改 T=100、只改线性项，全部 ≈0；只改 T=2 对 Δ=−1/+1 有 0.40/0.21，只改 T=5 对 Δ=−2/+2 有 0.44/0.23。
  - 所有效果在第 18–20 层后消失（信息已被搬走），与 F2 中的转折层一致。
- 解读：模型确实从 helix 子空间读取数字的"个位"部分（高频分量 T=2、T=5 起作用）。但十位信息主要不在拟合出的 helix 子空间里：Δ=±10 只改变 T=100 和线性分量，编辑毫无效果，而整位置替换能完美做到。
  → 对合作者：他的流形正则以 helix 为目标，但 OLMo 在两位数加法里真正使用的十位信息并不在 helix 的慢分量上。
- 下一步：exp1b 用"按位"基（十位 one-hot + 个位 one-hot，或十位圆 + 个位圆）拟合并做编辑，检验十位是否存在单独的编码。

## [2026-09-27] F4 两位数在操作数位置上是按位（十位 + 个位）编码的，十位不在 helix 上

## [2026-09-27] F6 main 在三项式上的错误几乎都是"少 10"，而最后一层状态里存着正确总和

- 设置：`Output ONLY a number.{a}+{b}+{c}=`，a,b,c∈10..99，总和≤99；1500 题，不按对错过滤。
  任务 `039-gap-s1-150000` / `041-gap-s2i1-step11931` / `042-gap-main`，commit b2c2d61。
  探针：核岭回归读到 helix 特征再取最近候选；按 (a,b) 对分组的 5 折交叉验证（测试数对都没见过）；读的是各层 decoder 输出中 '=' 位置的状态。
- main：

| 指标 | 值 |
|---|---|
| 模型首 token 准确率 | 0.764（98% 的回答是数字） |
| 模型个位 / 十位准确率 | 0.97 / 0.80 |
| 答错的题中恰好少 10（t−10） | 268 / ~354（其余多为 −2、−4、±10、−20） |
| 答错的题中个位正确 | 0.85 |
| 探针在 '=' 处解码总和（L26–31） | 0.99（个位 0.99，十位 1.00）；L20 为 0.28，L21 为 0.67，L24 为 0.96 |
| **模型答错的题里，探针解码正确的比例（L29）** | **0.99** |
| 模型对、探针错 | 0.00 |

- stage2 ingredient1 的结果几乎一样（模型 0.761；答错的题中，探针正确的比例为 0.99）。
- step150k：模型 0.073；探针最高 0.43（十位 0.85、个位 0.43），误差分布较散（−10、−12、−8……），模型答错的题中探针正确的比例为 0.42。
- 解读：在 main 上，送进输出头之前的最后一层（L31）状态，几乎对每道题都线性地编码着正确总和；而模型自己的输出头（final norm + unembedding，也是固定的线性读出）在约 1/4 的题上读成了 t−10。错误发生在"读出"这一步，而不是"计算"这一步。
  这是一个"表征了 ≠ 报告了"的具体例子，而且可以精确到一位数字（十位）。
- 注意：探针是有监督训练的线性读出，它能读出，说明信息存在；并不说明模型"本应"这样读。exp2f（任务 043–045）会检查误差是否与进位有关，用 logit lens 看 t−10 在哪一层压过 t，并测试沿模型自己的"十位"方向推一格能否修正答案。

## [2026-09-27] 方法记录：流形损失怎么写才真正约束"几何"

- v1（commit bce1699，已停用）：L = ||(h − μ) R − F_G(x)||²，R 是在 base 模型的 90 个数字均值上拟合的 4096 维岭回归读出。
  问题：90 个点在 4096 维里可以被线性地映射到**任何**目标（包括打乱的）上。实测 step10k 上，训练一开始 helix 损失约 0.026、打乱目标约 0.11（满分误差约 1）。
  这个损失等于"别让读出漂移"，不约束形状；各几何之间也没有差别（ReFT step10k：held-out 13.8–15.7%，none 13.8%）。
  step10k 的 LoRA/ReFT 和 step50k 的 ReFT（任务 056/057/059）是 v1 结果，只作参照。
- **合作者的做法有同类问题**：他在全部 4096 维上对 M(x) 做 MSE，而 M(x) 又来自第 0 位置（F1）。它约束的是"位置"，不是"形状"。
- v2（commit ae16987）：L_geo = mean_L (1 − CKA(H_L, F_G))，H_L 是 90 个前缀 "Q: x" 在 A 位置第 L 层的状态，每一步都重新计算。
  线性 CKA 只对旋转和整体缩放不变，所以只有表征本身的形状接近理想流形时，损失才会低。
  小模型验证：helix 目标把 CKA(helix) 从 0.06 推到 0.45–0.46，CKA(打乱 helix) 保持 0.10；打乱目标把 CKA(打乱) 推到 0.55–0.58，CKA(helix) 保持 0.05。
